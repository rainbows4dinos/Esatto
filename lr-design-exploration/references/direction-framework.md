# Direction framework

## Brief

Capture the user task and success criterion, target audience/context, known pain points with evidence, source artifacts/date, fixed requirements, available system assets, implementation limits and unresolved assumptions. Tie decisions to the actual task rather than a fashionable aesthetic. When `visual` is in focus, also capture the intended tone or perception (for example calm, authoritative, playful) and any brand constraints.

## Useful differences

Examples of meaningful axes, to use only when applicable:

| Axis | Possible contrast | Consequence to examine |
| --- | --- | --- |
| Task flow | Guided sequence / direct manipulation | Initial clarity versus expert speed |
| Information organization | Overview with drill-in / persistent workspace | Orientation versus simultaneous comparison |
| Disclosure | Essentials first / dense visible controls | Reduced scanning versus discovery cost |
| Decision support | Side-by-side comparison / ranked next action | User control versus decision effort |
| Navigation | Contextual path / stable global structure | Local relevance versus predictability |
| Layout | Columns or board / list / table / canvas | Overview versus detail per item |

Visual axes, for use when `visual` is in focus:

| Axis | Possible contrast | Consequence to examine |
| --- | --- | --- |
| Typographic voice | Editorial, serif-led / utilitarian sans | Character and hierarchy versus neutrality and scanning speed |
| Color strategy | Neutral with one accent / color-coded surfaces | Calm focus versus at-a-glance status |
| Density and rhythm | Generous whitespace / tight grid | Approachability versus information per screen |
| Shape language | Soft rounded containers / rules and hairlines | Friendliness versus precision |
| Imagery and iconography | Illustrative or photographic / purely typographic | Warmth and memorability versus restraint |
| Motion | Expressive transitions / near-static | Feedback and delight versus distraction and performance |

A difference is substantive if a user would notice a change in how they find, understand or complete the task. Two directions can reuse the same component system and still differ meaningfully. A new palette does not establish a new interaction concept, and a new interaction concept does not establish a new visual language. With `visual` in focus, a visual difference is substantive if a user would notice a different character, hierarchy, or perception, applied consistently across the screen.

## Direction card

- **Name and organizing idea:** describe the mechanism, not just a mood.
- **Intensity and lead layer:** the level, the layer the hypothesis is mainly about, and any incidental changes to other layers.
- **Lineage (seeded rounds):** the chain from the original through the seed, the seed traits preserved, and what this direction changes relative to the seed.
- **Hypothesis:** For [audience/context], [change] will improve [observable task outcome] because [mechanism]. For a visual lead: For [audience/context], [visual change] will make [perception, hierarchy, or legibility outcome] better because [mechanism].
- **Evidence and rationale:** source observations; separate assumptions and analogies.
- **Composition/flow:** primary action, content hierarchy, navigation, disclosure, key states.
- **Source contract:** what is preserved; explicit proposed deviations and why.
- **System fit:** reusable component IDs/variants, tokens/modes, missing capabilities, implementation cost.
- **Tradeoffs:** who benefits, who may struggle, accessibility risks, failure conditions.
- **Validation:** representative task, observable measure, disconfirming evidence, and unresolved dependencies. Visual directions can use first-impression or five-second tests, preference with stated reasons, and legibility and contrast checks.

## Fair comparison

Use the same representative task/data and equivalent fidelity. Show enough of each flow to expose costs; do not compare a polished happy path with an unfinished alternative. Include a baseline if available.

| Criterion tied to brief | Baseline | Direction A | Direction B | Evidence/confidence |
| --- | --- | --- | --- | --- |

Choose criteria such as task completion effort, comprehension, information visibility, recovery, perceived tone, visual hierarchy, legibility, accessibility, system fit and implementation cost only when relevant. Qualitative judgments are acceptable; explain the mechanism. If scoring is useful, define the scale and user-grounded weights before ranking. Do not manufacture numerical precision.

Record the recommendation, strongest counterargument, outstanding uncertainty and smallest useful validation step. If combining directions, describe and reassess the resulting flow instead of assuming all benefits combine without cost.
